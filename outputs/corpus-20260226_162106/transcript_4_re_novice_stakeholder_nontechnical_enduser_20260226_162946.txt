Interviewer: Good. Now about integrations — you mentioned using the statement system and merchant lookup. Which system is the source of truth for transaction details?

If that lookup fails I want a clear message and a way to flag the case and move on.

Stakeholder: From the cardmember database — that's where their contact info, billing address, and account-level stuff lives. Interviewer: Merchant details — where do you expect those to come from?

Stakeholder: The merchant database, yeah — same idea. We need merchant name, merchant category, contact info if available. So if the merchant lookup fails, the app should tell me why or let me attach a manual note.

Stakeholder: I'd rather it show cached or partial data with a clear warning and let me create or edit a case. I don't want the whole workflow blocked. If a rep needs temporary escalation there's usually a manual process now, but it should be smoother.

Stakeholder: Umm, well, we have regular reps, senior reps, and supervisors — and there are some external merchant reps who have limited access. Stakeholder: Absolutely. If someone gets temporary rights or someone leaves, that should show up somewhere. Auditors have asked us for evidence before. It should be clear who did what and when.

Stakeholder: We need to see who touched the case and when. Like if someone changed a status, added a note, sent correspondence, or adjusted an account — that should be visible. And if someone corrects a mistake, the previous entry should still be visible — don't let it disappear.

Stakeholder: Hmm, I think managers and audit folks should definitely see everything. Regular reps probably only need to see the history for cases they handle, but they shouldn't have the power to edit the audit entries. Keeping it visible but controlled is important.

Interviewer: If a user makes a correction, do you want the app to show both versions automatically?

Stakeholder: Yes, show both. If someone overwrites something the old entry should still be there with a note about who changed it and why. We had a situation once where a note was removed and it caused a big issue — we don't want that again.

Stakeholder: Don't show cryptic errors. Say something like "Transaction lookup failed — try again or flag for Ops" and give a way to save a draft.
